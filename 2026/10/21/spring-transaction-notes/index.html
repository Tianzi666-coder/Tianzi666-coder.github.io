Spring 事务失效的六种场景（附解决方案）

Tianzi666-coder2026-10-212026-10-20

@Transactional 加了却不回滚？基本就这六种原因。

1. 同类内部方法调用（最常见）

原因：Spring 事务靠 AOP 代理实现，this.b() 绕过了代理对象。

解决：

2. 方法不是 public

@Transactional 基于代理，private / protected / static / final 方法都失效。

3. 异常被自己 catch 了

事务管理器靠捕获异常决定回滚，你吞掉它就认为一切正常。

4. 抛的是受检异常

默认只对 RuntimeException 和 Error 回滚。抛 IOException 不会回滚。

解决：@Transactional(rollbackFor = Exception.class)

5. 数据库引擎不支持事务

MyISAM 不支持事务，表引擎必须是 InnoDB。

6. 多线程 / 异步

事务绑定在当前线程（ThreadLocal），子线程是独立的事务。

附加：传播行为搞错

REQUIRES_NEW 会挂起外层事务开新事务；如果外层回滚，内层已提交的数据不会回滚。

自检清单

  • 方法 public 吗？
  • 是通过代理（别的 Bean）调用的吗？
  • 异常没被吞掉吗？
  • rollbackFor 设了吗？
  • 表是 InnoDB 吗？
  • 是同一个线程里执行的？

面试一句话：Spring 事务本质是 AOP 代理 + ThreadLocal 绑定连接，所以绕过代理、换线程、吞异常都会失效。
