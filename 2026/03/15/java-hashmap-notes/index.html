Java 集合：HashMap 底层结构与扩容机制

Tianzi666-coder2026-03-152026-10-20

一句话总结

JDK 8 的 HashMap = 数组 + 链表 + 红黑树。默认容量 16，负载因子 0.75，扩容时容量翻倍。

底层结构

组成部分 作用
Node[] table 哈希桶数组，长度永远是 2 的幂
Node 链表 哈希冲突时用链地址法串起来
TreeNode 红黑树 链表长度 ≥ 8 且桶容量 ≥ 64 时树化，查询从 O(n) 降到 O(log n)

put 的核心流程

  1. hash(key)：(h = key.hashCode()) ^ (h >>> 16) —— 让高位参与运算，减少冲突；
  2. 定位桶：(n - 1) & hash，等价于对 n 取模，但 n 是 2 的幂所以能用位运算；
  3. 桶为空 → 直接放；桶非空 → 比对 hash 和 key，相同则覆盖，否则挂到链表/红黑树尾部；
  4. ++size > threshold → 触发 resize()。

为什么容量必须是 2 的幂

(n - 1) & hash 只有在 n 是 2 的幂时才等价于 hash % n，而且位运算更快。扩容时元素要么留在原位，要么移动 oldCap，不用重新计算 hash。

扩容（resize）

  • 触发条件：size > capacity * 0.75；
  • 新容量 = 旧容量 × 2，阈值也翻倍；
  • JDK 8 用高低位拆分（(e.hash & oldCap) == 0）避免 JDK 7 头插法导致的死循环。

面试常问

  • 为什么负载因子是 0.75？（空间与冲突概率的折中，泊松分布下链表长度 8 的概率极低）
  • 为什么树化阈值是 8、退化阈值是 6？（留缓冲，避免频繁转换）
  • HashMap 线程安全吗？（不安全，多线程扩容可能丢数据；并发用 ConcurrentHashMap）
  • key 为什么常用 String 或不可变对象？（hashCode 稳定，否则 put 进去就 get 不出来）
