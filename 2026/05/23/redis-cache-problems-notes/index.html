Redis 缓存三问 + 分布式锁：穿透/击穿/雪崩

Tianzi666-coder2026-05-232026-10-20

三个”经典问题”一句话区分

问题 现象 原因
穿透 大量请求查不存在的数据 恶意请求 or 逻辑漏洞，每次都打到 DB
击穿 单个热点 key 失效瞬间 大量请求同时回源
雪崩 大量 key 同时失效 TTL 设成同一时间，或 Redis 挂掉

解法

穿透

  1. 缓存空值（SET k "" EX 60），注意设短 TTL；
  2. 布隆过滤器：不存在的一定拦截，存在的不一定放行；
  3. 参数校验（id ≤ 0 直接拒绝）。

击穿

  1. 互斥锁：只放一个线程回源，其余等待重试（SETNX）；
  2. 逻辑过期：value 里存过期时间，异步刷新，期间返回旧值。

雪崩

  1. TTL 加随机值（base + random(0, 300)）；
  2. 多级缓存（本地 Caffeine + Redis）；
  3. 熔断降级、Redis 高可用（哨兵/集群）。

缓存一致性

Cache Aside 模式：先更新数据库，再删除缓存（不是更新缓存）。

为什么删而不更新？并发下”更新缓存”容易出现旧值覆盖新值；删除更简单可靠。

分布式锁（Redis 版）

三个要点：互斥（NX）、防死锁（PX 过期）、防误删（value 校验 + Lua 原子）。

生产环境更推荐 Redisson：自带看门狗自动续期、可重入、红锁。

面试常问

  • Redis 单线程为什么快？纯内存 + IO 多路复用 + 单线程无锁竞争；
  • 为什么用 Lua？保证”判断 + 删除”的原子性；
  • 锁过期了业务还没跑完怎么办？看门狗续期（Redisson）。
